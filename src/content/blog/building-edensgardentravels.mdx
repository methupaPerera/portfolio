# Building a Travel Website for a Real Client

Working on your own projects is comfortable.

Working for a real client is different.

Suddenly, every bug matters. Every delay matters. Every decision has consequences.

This is what I learned while building **Eden’s Garden Travels**.

---

## Why I Took This Project

As a student and web developer, I wanted:

- Real-world experience
- Client communication practice
- A serious portfolio project
- Confidence in my skills

Tutorials are safe.  
Clients are honest.

This project forced me to grow.

---

## Project Goals

The client wanted a website that could:

- Display tour packages
- Manage content easily
- Support multiple languages
- Allow online payments
- Serve both admins and customers

Simple on paper.

Complex in reality.

---

## Tech Stack

For this project, I used:

- **Next.js** for performance and routing
- **React** for UI components
- **Tailwind CSS** for styling
- **API routes** for backend logic
- **Payment gateway** for transactions
- **MDX** for blog content

This stack helped me move fast without sacrificing quality.

---

## Key Features

### 1. Responsive Design

The site works smoothly on:

- Phones
- Tablets
- Laptops
- Large screens

Tourists browse everywhere.  
The site had to follow them.

---

### 2. Admin Dashboard

Admins can:

- Add packages
- Edit content
- Manage bookings
- Update prices

No developer needed for daily updates.

That’s real usability.

---

### 3. Customer Dashboard

Users can:

- View bookings
- Track payments
- Manage profiles
- Contact support

It turned a website into a system.

---

### 4. Payment Integration

Online payments were challenging.

Handling:

- Validation
- Security
- Errors
- Confirmations

taught me how serious “real-world code” is.

---

### 5. Multilingual Support

Supporting multiple languages meant:

- Clean data structure
- Careful UI design
- Consistent translations

Small detail. Big impact.

---

## Biggest Challenges

### 1. Understanding Requirements

Clients don’t speak “developer.”

They speak in ideas.

My job was to translate ideas into features.

That took patience.

---

### 2. Time Management

Balancing:

- Studies
- Development
- Testing
- Fixes

was harder than expected.

Deadlines don’t care about excuses.

---

### 3. Debugging Production Issues

Some bugs only appear after deployment.

No local comfort zone.

Just logs, pressure, and problem-solving.

---

## What I Learned

This project taught me:

- How to work with clients
- How to plan before coding
- How to write maintainable code
- How to handle responsibility
- How to deliver finished products

“Finished” is rare.  
I’m proud of this one.

---

## What I’d Do Differently

If I rebuilt it today, I would:

- Improve documentation
- Automate testing
- Optimize loading further
- Add analytics earlier

Every project becomes a teacher later.

---

## What’s Next

Next, I want to:

- Take more client projects
- Build SaaS tools
- Improve backend skills
- Write deeper case studies

One solid project at a time.

---

## Final Thoughts

Client work is uncomfortable.

That’s why it’s valuable.

You stop building “practice apps”  
and start building solutions.

If you’re waiting for confidence, don’t.

Build first. Confidence follows.

Thanks for reading.
